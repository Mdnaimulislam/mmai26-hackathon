# Clinical Strand Demo — Reference Implementation

This is a reference implementation of one possible solution to the clinical strand challenge. It shows what a completed solution can look like — not a template you must follow.

**Challenge concept:** Post-surgical Step-down Monitoring Brief — a handover tool that generates a personalised ward monitoring protocol for each patient based on AI-predicted 30-day complication risk.

## Step 1 — Set Up Your Environment

Using a virtual environment is strongly recommended to avoid package conflicts.

```bash
# Create and activate a virtual environment
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

# Install all dependencies (run from the demo/ directory)
pip install -r requirements.txt
```

`requirements.txt` installs:

| Package | Purpose |
|---|---|
| streamlit | Dashboard app |
| pandas, numpy | Data handling |
| scikit-learn | Preprocessing, metrics, TF-IDF |
| torch | Required by PyKale (Model A) |
| pykale | Multimodal neural network (Model A) |
| matplotlib, plotly | Visualisations |
| joblib, scipy | Model serialisation, stats |

> **Note:** `torch` and `pykale` are the heavier installs (~1 GB). Training Model A takes ~30–60 seconds on CPU.

## Step 3 — Run the Notebooks in Order

All data files are pre-included in `data/raw/` — no data download is needed. Run the three notebooks **in sequence**; each notebook writes outputs that the next one reads.

### Notebook 00 — Data Exploration (`00_data_explore.ipynb`)

**What it does:** profiles the synthetic dataset, identifies MNAR patterns, and highlights the clinical subgroups your models must handle correctly.

**What to look for:**
- Complication rates vary widely across surgery types (cardiac ~62%, orthopaedic ~6%)
- Note absence is concentrated in the highest-risk patients — MNAR, not random
- Vascular patients have suppressed heart rate and lactate due to beta-blockade — a model relying on vitals alone will miss them

**Key expected outputs:**

```
Shape: (500, 37)
Complication rate: 25.4% | Has notes: 68.8% | Blood loss MNAR: 33.8%

Note missingness:  cardiac 58% | vascular 42% | abdominal 21% | orthopaedic 14%
Blood loss MNAR:   cardiac 51% | vascular 45% | abdominal 24% | orthopaedic 24%

Vascular: HR mean = 70 bpm, ICU lactate = 0.95  (lowest of all surgery types)
```

**Produces:** no files — analysis only. Answer the reflection questions at the end before proceeding; they directly inform your deployment verdict in the app.

---

### Notebook 01 — Preprocessing & Split (`01_preprocess_and_split.ipynb`)

**What it does:** applies median imputation to numeric features (excluding MNAR columns), then creates stratified 70/15/15 train/val/test splits preserving the complication rate.

**Key expected outputs:**

```
No NaN in numeric feature columns — no imputation needed.
Remaining NaN (excl. MNAR columns): 0

train : n= 350  complication=25.4%  notes=70.3%
val   : n=  75  complication=25.3%  notes=72.0%
test  : n=  75  complication=25.3%  notes=58.7%
```

**Produces:** `data/processed/train.csv`, `val.csv`, `test.csv`

---

### Notebook 02 — Model Training (`02_train_models.ipynb`)

**What it does:** trains Model A (PyKale multimodal fusion) on the train split, evaluates on val, checks calibration, and saves artefacts. Training takes ~30–60 seconds on CPU.

**Model A — PyKale Multimodal Fusion:**

| Branch | Input | Architecture |
|---|---|---|
| Tabular | Surgical context + ICU severity (12 features) | FCNet encoder |
| Text | TF-IDF on clinical notes (200 features) | FCNet encoder |
| Time series | Slope/variability from hourly vitals (18 features) | FCNet encoder |

**Key limitation:** when notes are absent (MNAR ~32%), the text branch receives a zero vector, causing systematic underestimation of risk for note-absent patients — concentrated in cardiac/vascular cases.

**Key expected outputs:**

```
Model A | Val AUROC=0.83–0.89

MNAR preview:
  With notes:    AUROC=0.85–0.90
  Without notes: AUROC=0.70–0.80
  Gap ≈ 0.05–0.15  >>> MNAR signal detected
```

**Produces:** `saved_models/model_a.joblib`, `saved_metrics/training_metrics.csv`

```bash
# Run from the demo/ directory
```

1. Click **Run Demo Pipeline** to train Model A, generate metrics, and build the evidence dashboard.
2. Review the **Evidence Dashboard** output (metrics + subgroup gaps).

The app does **not** complete deliverables for you — teams must fill `reference/omaib_pathway.json` and `reference/model_safety_report.json` with their own evidence-backed narratives, verdicts, and conditions.

## Data Guide

| File | Rows | Description |
|---|---|---|
| `tabular.csv` | 500 | One row per patient. Feature matrix used by the notebooks and models. |
| `notes.csv` | 344 | One row per patient with a clinical note. MNAR — absent patients are higher-risk. |
| `vitals_series.csv` | 12,000 | 24 hourly rows per patient (heart rate, RR, SpO₂, SBP, temp, lactate). |

**MNAR columns in `tabular.csv`:**
- `note_risk_score` — NLP-derived risk score; NaN when no note was written (~31% missing, concentrated in cardiac/vascular)
- `blood_loss_ml` — intra-operative blood loss; NaN when not recorded (~34% missing, concentrated in cardiac/vascular)
- `blood_loss_imputed` — mean-filled version; used by Model A but underestimates complex cases
- `blood_loss_missing` — binary flag (1 = MNAR); Model A uses this alongside the imputed value

See `data/raw/README.md` for the full column-by-column feature guide including value ranges, MNAR patterns, and model usage notes.

**This is synthetic data.** All patient identifiers and clinical values are generated. Do not use this data for your own submission — use the strand dataset provided.

## Troubleshooting

**`FileNotFoundError: train.csv not found`**
Run `01_preprocess_and_split.ipynb` first to generate the processed splits.

**`ImportError: No module named 'kale'`**
PyKale was not installed. Run `pip install pykale>=0.2.0`. Also ensure `torch>=2.0` is installed first, as PyKale depends on PyTorch.

**Kernel not found in VS Code**
Click the kernel indicator in the top-right of the notebook, then select **Python Environments** and choose the `.venv` you created.

**`streamlit: command not found`**
Activate your virtual environment first (`.venv\Scripts\activate` on Windows, `source .venv/bin/activate` on macOS/Linux), then run `streamlit run streamlit_app.py`.

**App shows "Run notebooks first" info message**
The pipeline button needs `data/processed/train.csv` and `test.csv`. Run notebooks 01 and 02 in order to generate these files.
